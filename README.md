# Luna · 本地音乐与音声库

> **V1.1.0** · Windows 桌面应用 · 本地运行、不联网、不上传任何数据

把堆在硬盘里、数量庞大又没分类的专辑，整理成一面**可浏览、可检索、可播放**的专辑墙。
Luna 为两类形态差异很大的内容分别建模——**普通音乐专辑**按专辑/曲目组织，
**音声（ASMR）作品**按「发行 → 版本 → 轨道」三层组织（RJ 号、差分版本、视频版、特典）。
V1.1 起还支持**压缩包只读挂载**：不解压也能把包内作品摆上专辑墙。

**技术栈**：Node.js + 内置 `node:sqlite` + 零构建原生前端；桌面版由 Electron 打包。
**运行时依赖仅 3 个**：`express`、`music-metadata`、`node-taglib-sharp`（都是纯 JS，无原生编译）。

## 桌面版（Windows 便携版）

打包产物在 `Release/`：

| 产物 | 说明 |
| --- | --- |
| **`Release/Luna_v1.0.exe`** | 单文件便携版，双击即用 |
| `Release/data/` | **全新空库**（纯净发布，不含任何开发期记录） |

**便携的含义**：只要 `Luna_v1.0.exe` 旁边有 `data/` 目录（含 `library.db`），它就用那份数据；
没有则退回 `%APPDATA%\Luna\data`。发布包里已经带了干净的空库，所以
**把 exe 和 data 一起拷到任意位置或 U 盘即可使用**，数据不外溢。

首次启动进「扫描音乐库」添加你的目录即可。

```powershell
pnpm release          # 完整测试 + 打包 + 生成纯净数据
```

## 快速开始（开发模式）

```powershell
pnpm install
node_modules\electron\dist\electron.exe . --remote-debugging-port=9360   # 桌面窗口（推荐）
# 或
pnpm start            # 只起后端，浏览器打开 http://127.0.0.1:8799
```

1. 点左侧「音乐库」旁的 **+**，粘贴音乐目录（如 `E:\Music\Album`），可顺手填一个**库显示名**；
2. 点「添加并扫描」，等待进度条跑完；
3. 专辑墙出现后：点封面 ▶ 播放整张 / 点卡片进详情 / 点 🏷 打标签。

### 常用命令

```powershell
pnpm start            # 启动后端服务（默认 8799）
pnpm dev              # 开发模式（--watch，改后端自动重启）
pnpm electron         # 启动 Electron 桌面窗口
pnpm scan -- "E:\Music"      # 命令行扫描（不开界面）
pnpm scan -- --all           # 重扫全部已登记的音乐库

pnpm test             # 局部测试：按 git 改动自动挑区域
pnpm test:unit        # 只跑单元测试（约 1 秒）
pnpm test:full        # 完整测试流程（发布前必跑）
pnpm test:list        # 列出所有测试区域

pnpm release          # 完整测试 + 打包 + 纯净数据
```

> 完整说明见 [`docs/测试流程.md`](docs/测试流程.md)。

## 能力总览（V1.1.0）

### 核心六项

| 能力 | 说明 |
| --- | --- |
| 多音乐库 | 添加任意多个本地目录；**重命名显示名**（仅软件内，不触碰文件系统） |
| 元数据读取与**写回** | 读取并修复标签后写回文件；五道关口的安全框架 + 一键撤销 |
| 多标签分类 | 专辑级多标签、8 色、置顶、重命名、合并、批量打标；AND/OR 检索 |
| 歌词与字幕 | LRC / VTT / SRT / ASS 四种格式 + 台本镜像目录；滚动高亮、点击跳转、字号 A+/A− |
| 四种播放模式 | 列表循环 / **顺序播放** / 单曲循环 / 随机播放 |
| 可视化专辑墙 | 卡片墙、封面、版本角标、三档尺寸、多选批量操作 |

### 压缩包只读挂载（V1.1 新增）

**不解压**就能把压缩包里的作品摆上专辑墙并正常分类。压缩包**永远只读**，Luna 不写、不改、不重命名任何包。

- **零解压扫描**：只读 ZIP 中央目录拿清单（实测 63 条目 9 ms），全程不解压音频数据
- **虚拟路径接入音声模型**：把包文件当作一层虚拟目录，因此版本、差分、特典、RJ 号识别**全部自动成立**
- **文件名编码嗅探**：不信任 UTF-8 标志位，按 `UTF-8 → Shift-JIS → GB18030` 择优（音声包实测多为 Shift-JIS）
- **包内封面**：解出封面图并进内容寻址存储；唯一需要解压的对象
- **只读能力边界**：当前**目录扫描 + 入库 + 封面 + 分类**可用；**播放要等 P2**（`.lam-cache/` 按需解码）
- 详细设计与 P2–P4 路线图见 [`docs/压缩包支持设计.md`](docs/压缩包支持设计.md)

### 音声（ASMR）作品

一张音声发行 = 专辑墙上一张卡。

- **三层模型**：发行 → 版本（本篇 / 无音效 / 无饮尿…）→ 轨道
- **版本以文件夹名为准**，标签仅作交叉校验；冲突时标 ⚠ 提示人工确认
- **差分标注**：同一版本下多个文件按括号标记区分，不会出现两个同名按钮
- **轨道合并**：按轨号合并成一行，行内按钮一键切换版本播放
- **格式优先级**：每个版本内 wav 优先于 mp3；`.mp4` 作为独立「视频版」按钮
- **特典分离**：`おまけ / 特典` 轨道收进可折叠分组；`alarm` 等噪声文件忽略
- **角标**：版本数 / 含特典 / 含视频版
- **不写回**：音声的标题、艺术家、社团**只存库内**，绝不修改用户文件

### 收藏体系

| 入口 | 收录 |
| --- | --- |
| 喜欢的ASMR | 音声发行 |
| 喜欢的专辑 | 普通音乐专辑 |
| 喜欢的音乐 | 单曲（音声曲目不参与） |

### 艺术家决策（防错）

标签里的 `albumartist` 与曲目 `artist` 冲突时**以 artist 为准**，冲突值降级为「标签建议」并在详情页提示，
由你选择**采用它**或**保持现状**；任一选择后不再重复询问。手工填写的值永不被扫描覆盖。
填写社团/艺术家时会自动套用到文件夹名含该文字的其它音声发行。

### 安全写回

写标签是本产品唯一的不可逆风险来源，所有写操作走同一套框架（`server/write-jobs.mjs`）：

```
① 写前检查（占用 / 权限 / 磁盘空间）
② 乐观锁（编辑期间文件被外部改动则拒绝写入）
③ 复制出工作副本 —— 原文件在此之前完全不动
④ 写入标签到工作副本
⑤ 用同一解析器回读校验
⑥ 原文件移入 .lam-undo/<jobId>/，工作副本原子改名就位
⑦ 重新解析并同步索引；失败可一键撤销
```

## 项目结构

```
Luna/
├── electron/           桌面外壳（主进程、菜单、日志、数据目录决策）
├── server/             后端（Express 5 + node:sqlite）
│   ├── asmr.mjs        音声路径/标签解析（纯函数，无 I/O）
│   ├── scanner.mjs     扫描与入库
│   ├── zip-reader.mjs  压缩包只读读取（ZIP 中央目录 + 编码嗅探 + 单成员解出）
│   ├── db.mjs          数据访问（schema v6）
│   ├── lyrics.mjs      歌词与字幕解析匹配
│   ├── writers.mjs     标签写入适配器（taglib-sharp）
│   ├── write-jobs.mjs  写操作安全框架
│   ├── tags.mjs        标签体系
│   ├── completeness.mjs 信息完整度
│   ├── maintenance.mjs 封面回收、备份、维护
│   └── index.mjs       HTTP 接口与静态资源
├── public/             前端（零构建，原生 ES Module）
├── test/               单元测试（node --test）
├── tools/
│   ├── check/          界面检查套件 + 测试运行器
│   ├── release/        纯净发布脚本
│   └── dev/            破坏性/探索性手工脚本（不在自动流程内）
├── docs/               产品设计文档、音声设计、压缩包支持设计、测试流程
├── build/              打包用图标（由 icon/ 生成）
└── icon/               图标源图
```

数据目录（便携模式下为 `<exe>/data/`）：

```
data/
├── library.db     索引 + 用户资产（标签、显示名、收藏、社团、艺术家决策）
├── covers/        封面内容寻址存储 + thumbs/ 缩略图
├── backup/        用户资产自动备份
└── undo/          写操作的撤销副本
```

## 数据与安全

- **不联网**：全部逻辑在本机，无遥测、无上传
- **用户资产**：标签、库显示名、豁免项、收藏、社团、艺术家决策**不可从文件重建**，变更后自动备份并可导出
- **索引可重建**：曲目/专辑索引可从文件重新扫描得到
- **静默写入是不允许的**：任何修改用户文件的操作都必须先预览影响面
- **音声元数据只存库内**：绝不写回音频文件

## 技术栈

| 方面 | 选择 | 理由 |
| --- | --- | --- |
| 运行时 | Node.js ≥ 22.5（Electron 37 内置 22.16） | 需要内置 `node:sqlite`，零原生依赖 |
| 后端 | Express 5 | 轻量，够用 |
| 数据库 | `node:sqlite` | 内置，无编译负担 |
| 标签读取 | `music-metadata` | 格式覆盖广 |
| 标签写入 | `node-taglib-sharp` | 纯 JS，无需原生模块 |
| 前端 | 原生 ES Module + CSS | **零构建**，改完刷新即生效 |
| 打包 | electron-builder 26 | `asar: false`（ESM 动态 import 不走 asar 补丁） |

## 已知限制（V1.1.0）

| 限制 | 说明 |
| --- | --- |
| 压缩包内曲目**暂不能播放** | P1 只做清单入库；按需解码与流播在 P2（设计文档 §7） |
| 仅支持 ZIP | 7z / RAR / 分卷 / 加密包在 P4；不支持的包会被如实计数并出现在扫描报告里 |
| 图标源图仅 64×64 | 放大到 256 会偏软；16px 下花体字与波形不可辨 |
| 未实现 DSD / 整轨镜像的转码播放 | 此类文件可入库，但浏览器无法直接解码 |
| 视频版不参与音频队列 | 顺序播放时跳过视频 |
| 台本仅在无字幕时启用 | 同目录存在字幕文件时优先字幕，暂不能手动切换 |
