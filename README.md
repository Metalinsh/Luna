# Luna · 本地音乐与音声库

> **V1.2.6** · Windows 桌面应用 · 本地运行、不联网、不上传任何数据

把堆在硬盘里、数量庞大又没分类的专辑，整理成一面**可浏览、可检索、可播放**的专辑墙。
Luna 为两类形态差异很大的内容分别建模——**普通音乐专辑**按专辑/曲目组织，
**音声（ASMR）作品**按「发行 → 版本 → 轨道」三层组织（RJ 号、差分版本、视频版、特典）。
V1.1 起还支持**压缩包只读挂载**：不解压也能把包内作品摆上专辑墙。

**技术栈**：Node.js + 内置 `node:sqlite` + 零构建原生前端；桌面版由 Electron 打包。
**运行时依赖仅 3 个**：`express`、`music-metadata`、`node-taglib-sharp`（都是纯 JS，无原生编译）。

## 桌面版（Windows 便携版）

打包产物在 `Release/`：

| 产物 | 说明 |
| --- | --- |
| **`Release/Luna_v1.2.6/Luna.exe`** | 程序主文件（免安装目录版）。**目录与压缩包用完整版本号命名**（自 v1.2.3 起），一眼能看出拿的是哪一版 |
| `Release/Luna_v1.2.6/data/` | **全新空库**（纯净发布，不含任何开发期记录；schema v12）+ **DLsite 索引**（`data/Dlsite/rj_index.sqlite3`，约 19 MB） |
| `Release/Luna_v1.2.6.zip` | 整个程序目录打包，解压即用 |

> **DLsite 索引随包分发**：发布包自带 `data/Dlsite/rj_index.sqlite3`（7.8 万条），
> 装好就能按 RJ 号自动补社团 / 声优。想换新索引只要**替换这一个文件**（Luna 只读它，不写），
> 下一轮扫描自动对齐；升级时 `data/` 整个保留，索引也跟着保留。

**便携的含义**：只要 `Luna.exe` 旁边有 `data/` 目录（含 `library.db`），它就用那份数据；
没有则退回 `%APPDATA%\Luna\data`。发布包里已经带了干净的空库，所以
**把整个 `Luna_v1.2.6/` 文件夹拷到任意位置或 U 盘即可使用**，数据不外溢。

> **升级务必保留自己的 `data/`**：标签、收藏、手工封面、豁免项、歌词关联、排除清单全在里面
> （外加 `data/covers/` 的封面图片、`data/config.json` 的设置）。换新版时**只覆盖程序文件**，
> 把旧 `data/` 整个拷到新版目录下即可 —— schema 会自动迁移，用户资产不受影响。
> 直接整包替换会把发布包自带的空库一起带进来，看起来就像"标签全没了"。

首次启动进「扫描音乐库」添加你的目录即可。

```powershell
pnpm release                          # 按改动测试 + 打包 + 生成纯净数据
```

## 快速开始（开发模式）

```powershell
pnpm install
node_modules\electron\dist\electron.exe . --remote-debugging-port=9360   # 桌面窗口（推荐）
# 或
pnpm start            # 只起后端，浏览器打开 http://127.0.0.1:8799
```

1. 点左侧「音乐库」旁的 **+**，粘贴音乐目录（如 `E:\Music\Album`），可顺手填一个**库显示名**；
2. 点「添加并扫描」，等待进度条跑完；
3. 专辑墙出现后：点封面 ▶ 播放整张 / 点卡片进详情 / 点 🏷 打标签。

### 常用命令

```powershell
pnpm start            # 启动后端服务（默认 8799）
pnpm dev              # 开发模式（--watch，改后端自动重启）
pnpm electron         # 启动 Electron 桌面窗口
pnpm scan -- "E:\Music"      # 命令行扫描（不开界面）
pnpm scan -- --all           # 重扫全部已登记的音乐库

pnpm test             # 局部测试：按 git 改动自动挑区域
pnpm test:unit        # 只跑单元测试（约 1 秒）
pnpm test:audit       # 测试内容审计：找重复断言/用例（全面测试前必跑）
pnpm test:full        # 完整测试流程（**仅当明确要求全面回归时**）
pnpm test:list        # 列出所有测试区域

pnpm release                          # 默认：只测「相对上一版有改动」的区域 + 打包 + 纯净数据
pnpm release -- --areas=archive,lyrics # 改动落在公共文件时，按功能明确指定要测的区域
pnpm release -- --full-tests          # 打包 + 完整测试流程（用户明确要求时才用）
```

> **测试范围约定**：日常与发布都只验证**有改动的功能**；全面回归只在明确要求时跑，
> 且开跑前先用 `pnpm test:audit` 复核一遍测试内容、剔除重复项。
> 完整说明见 [`docs/测试流程.md`](docs/测试流程.md)。

## 能力总览（V1.2.6）

### V1.2.6 变化

| 变化 | 说明 |
| --- | --- |
| **不再提醒信息缺失** | 专辑墙卡片的「⚠ 待完善 / ⚠ 关键缺失」角标、侧栏「待完善 N」入口与徽标、整个待完善工作台、专辑详情页的缺失项 chips（缺年代 / 缺流派 / 缺封面…）与「忽略提醒」、统计页的「信息完整度 / 待完善专辑」两张卡片——全部去掉，以后不再有任何缺失信息提醒。**完善信息的能力一件没少**：编辑信息抽屉、填写社团 / 艺术家、批量填写、封面管理、写回与撤销都照旧 |
| **扫描后标签栏自动刷新** | 修复扫描结束后标签栏不更新的问题：扫描完成时改为串行「库列表 → 确定当前库 → 标签栏 → 当前视图」。原先并行执行时，标签栏可能按「还没选库 / 旧库」的类别去取标签，初次扫描 ASMR 库后识别出的标签一个都不显示，重启软件才正常 |
| **三大分类独立展开** | 标签栏的风格 / 社团 / CV 三栏各展开各的：点某一栏的「＋ 还有 N 个」只展开那一栏，其它栏保持折叠 |
| **展开后不再撑爆画面** | 标签栏展开后高度上限为**当前窗口的 1/3**，超出在栏内上下滚动；表头（清除筛选 / 标签套别 / 封面尺寸）滚动时固定可见 |

### V1.2.6 修复（同版本重发）

| 问题 | 说明 |
| --- | --- |
| ASMR 库里没有 RJ 号的作品被当成普通专辑 | 以前「音声 / 普通专辑」的分流只看路径里有没有 RJ 号，而「ASMR」标签是按目录名判定，两套口径不一致：丢进 ASMR 库但文件名/目录名不带 RJ 的作品（例如 `[Comiket 91][かの仔] かのコレクション.zip`）会挂上 ASMR 标签、却按普通专辑解析——详情页是普通样式、压缩包也按普通专辑读。现在**库目录名含 ASMR 的整库都走音声三层模型**：有 RJ 仍按 RJ 定发行根，没有 RJ 就按「库下的一级目录」定（一个作品一个文件夹），目录里的版本 / 特典子目录正常进版本层；ASMR 库里的压缩包整包按音声发行挂载，不再要求包内有 RJ。非 ASMR 库维持「有 RJ 才走音声」不变。压缩包「size + mtime 没变就跳过」的快路径会先看这个包当前挂在哪类专辑上，类别不对就强制重建一次——老库扫一次即治愈 |

### V1.2.5 新增

| 能力 | 说明 |
| --- | --- |
| **按 RJ 号自动补社团 / 声优** | 音声（ASMR）发行入库后，用它的 **RJ 号**去本地 DLsite 索引（`Dlsite/rj_index.sqlite3`，7.8 万条）里精确查一条记录：查到就把**社团**写进「社团」字段、把**声优**写进「艺术家」字段，并为两者各打一个**同名标签**（分类分别是社团 / CV，落在 ASMR 那一套里，关联来源记为 `dlsite`）。查不到就什么都不做——不猜、不做名称模糊匹配，等你手工填。RJ 号两种长度（`RJ123218` / `RJ01128508`）都按原样精确匹配，**不补零** |
| **只填空位，不覆盖你的手工值** | 字段有值就不动（包括你手填的、标签识别出的、以及正在等确认的「建议值」）；标签则是按「RJ + 该补哪些标签」的签名**只补一次** —— 你在界面上删掉的社团 / CV 标签不会在下次扫描时自己长回来；索引里那条作品的社团或声优名单变了，签名失效，才会按新数据重新补。自动补的声优来源记为 `dlsite`，与手工值一样**锁定**，后续扫描不会把它清空 |
| **索引更新跟得上** | 换掉 `data/Dlsite/rj_index.sqlite3` 后下一轮扫描自动对齐：旧标签（`source='dlsite'`）里已不在新数据中的会被**撤掉**，不会新旧并存；当初由索引填进「社团 / 艺术家」字段、且你没手工改过的值会跟着修正；手工填的值一律不动 |
| **存量专辑扫一次就补齐** | 补齐放在扫描末尾单独一趟，遍历库里所有带 RJ 号的音声发行。这样即使压缩包被 `size + mtime` 增量跳过（根本不走入库流程），存量库的压缩包专辑也能补上 —— 实测 11 张音声专辑全部按索引对齐 |
| **索引放哪都行** | 优先读 `data/Dlsite/rj_index.sqlite3`（跟着你的 `data/` 走，升级不丢，替换文件即更新），没有则读程序目录的 `Dlsite/`。`/api/health` 会如实报出用的是哪个文件、多少条；扫描完成时会提示「DLsite 命中 N 张」，找不到索引也会明确告知 |

### V1.2.3 修复（同版本重发）

| 问题 | 说明 |
| --- | --- |
| 压缩包字幕匹配不到 | 库内虚拟路径与专辑键原先用 **NUL** 作分隔符，而 Electron 内置 Node 22.16 的 `node:sqlite` **读回含 NUL 的文本会从 NUL 处截断**（开发/测试用的系统 Node 24 不会）。桌面版因此把 `…x.zip␀曲.mp3` 读成 `…x.zip`，包内歌词匹配恒不命中。改为 `PERSIST_SEP`（0x01）+ schema **v11** 迁移改写存量数据。同一根因还顺带修好：压缩包专辑的**封面补全**走错分支、「从库中移除」的**按键匹配**失效（此前只靠路径兜底才没暴露） |
| 单曲详情页不跟随外观 | 点左下角封面进入的单曲/歌词详情页原先写死了深色渐变底与 `#fff`/`#cdc6ff` 文字色，**对深浅模式、背景图、背景透明度三样全都不响应**（浅色模式下仍是黑底）。现在与主内容区共用同一套变量：基色走 `--bg-surface`（随主题与透明度），背景图作为下层、基色作为上层，与主界面观感一致 |

### 压缩包只读挂载与播放（V1.1 新增）

**不解压**就能把压缩包里的作品摆上专辑墙、并且**直接播放**。压缩包**永远只读**，Luna 不写、不改、不重命名任何包。

- **零解压扫描**：只读 ZIP 中央目录拿清单（实测 63 条目 9 ms），扫描阶段不解压音频数据
- **虚拟路径接入音声模型**：把包文件当作一层虚拟目录，因此版本、差分、特典、RJ 号识别**全部自动成立**
- **文件名编码嗅探**：不信任 UTF-8 标志位，按 `UTF-8 → Shift-JIS → GB18030` 逐条打分 + **整包多数票**统一裁决
- **按需解码播放**：点播放时先问「仅此单曲 / 整张专辑 / 暂不」，确认后把包内文件**流式解码**到缓存再播放
  （实测 1.3 MB 成员 14 ms、整张 0.61 GB 约 2.8 秒；已缓存的成员切轨不再解码）
- **缓存管理**：缓存目录可配置（默认 `<应用根>/luna_cache`）、容量上限可设（默认 20 GB）、
  超限时**放弃读取并提示文件过大**、按最近使用时间 LRU 回收、支持一键清空
- **包内封面**：解出封面图并进内容寻址存储。**音声发行与普通音乐专辑共用同一套挑选口径**（先「封面」类目录 → 再 cover/package 类文件名 → 最后取体积最大的一张）；普通音乐专辑只看**自己所在目录的子树**，子树里没图才退回整包，多专辑包不会串图。补封面在扫描的补充阶段完成，所以**老库扫一次就能补上**，压缩包本身始终只读
- **包内歌词**：包内字幕（`.lrc` / `<音频名>.mp3.vtt` / `.srt` / `.ass` / 整专共用的 `album.lrc`）用与磁盘**同一套匹配阶梯**识别，**不预读也能看**（现场只解出那一个几十 KB 的小文件）；**预读专辑时歌词一并落盘**，之后打开歌词零解压。清除该专辑缓存会连歌词一起清掉
- **预读专辑 / 清除缓存**：专辑详情页两个按钮，各带确认框 —— 整张预读完成后**自动打上「已预读」标签**
  （归入「风格」栏并**固定排在该栏首位**，可直接在专辑墙筛选）；清除缓存只清**这一张**专辑的缓存，并撤下该标签
- 详细设计与实测数据见 [`docs/压缩包支持设计.md`](docs/压缩包支持设计.md)

### 音声（ASMR）作品

一张音声发行 = 专辑墙上一张卡。

- **三层模型**：发行 → 版本（本篇 / 无音效 / 无饮尿…）→ 轨道
- **版本以文件夹名为准**，标签仅作交叉校验；冲突时标 ⚠ 提示人工确认
- **差分标注**：同一版本下多个文件按括号标记区分，不会出现两个同名按钮
- **轨道合并**：按轨号合并成一行，行内按钮一键切换版本播放
- **格式优先级**：每个版本内 wav 优先于 mp3；`.mp4` 作为独立「视频版」按钮
- **特典分离**：`おまけ / 特典` 轨道收进可折叠分组；`alarm` 等噪声文件忽略
- **角标**：版本数 / 含特典 / 含视频版
- **不写回**：音声的标题、艺术家、社团**只存库内**，绝不修改用户文件

| --- | --- |

### 艺术家决策（防错）

标签里的 `albumartist` 与曲目 `artist` 冲突时**以 artist 为准**，冲突值降级为「标签建议」并在详情页提示，
由你选择**采用它**或**保持现状**；任一选择后不再重复询问。手工填写的值永不被扫描覆盖。
填写社团/艺术家时会自动套用到文件夹名含该文字的其它音声发行，并为该名称**自动建立同名标签**
（打到本次填写的与被套用的全部作品上；已有同名标签则直接复用）。社团标签自动落在专辑墙上方的**「社团」栏**、
艺术家标签落在 **「CV」栏**，风格类自建标签在「风格」栏 —— 三栏可分别展开、逐栏点选筛选，标签页里也能改归类。

### 安全写回

写标签是本产品唯一的不可逆风险来源，所有写操作走同一套框架（`server/write-jobs.mjs`）：

```
① 写前检查（占用 / 权限 / 磁盘空间）
② 乐观锁（编辑期间文件被外部改动则拒绝写入）
③ 复制出工作副本 —— 原文件在此之前完全不动
④ 写入标签到工作副本
⑤ 用同一解析器回读校验
⑥ 原文件移入 .lam-undo/<jobId>/，工作副本原子改名就位
⑦ 重新解析并同步索引；失败可一键撤销
```

```

│   ├── write-jobs.mjs  写操作安全框架
│   ├── tags.mjs        标签体系
│   ├── completeness.mjs 信息完整度
│   ├── maintenance.mjs 封面回收、备份、维护
│   ├── collection.mjs  压缩包缓存与按需解码（容量判定 / 流式落盘 / LRU）
│   └── index.mjs       HTTP 接口与静态资源
├── public/             前端（零构建，原生 ES Module）
├── test/               单元测试（node --test）
├── tools/
│   ├── check/          界面检查套件 + 测试运行器
│   ├── release/        纯净发布脚本
│   └── dev/            破坏性/探索性手工脚本（不在自动流程内）
├── docs/               产品设计文档、音声设计、压缩包支持设计、测试流程
├── build/              打包用图标（由 icon/ 生成）
└── icon/               图标源图
```

数据目录（便携模式下为 `<exe>/data/`）：

```
data/
├── library.db     索引 + 用户资产（标签、显示名、收藏、社团、艺术家决策）
├── Dlsite/        DLsite 元数据索引（rj_index.sqlite3，随包分发，只读）
├── covers/        封面内容寻址存储 + thumbs/ 缩略图
```

## 数据与安全

- **不联网**：全部逻辑在本机，无遥测、无上传
- **用户资产**：标签、库显示名、豁免项、收藏、社团、艺术家决策**不可从文件重建**，变更后自动备份并可导出
- **索引可重建**：曲目/专辑索引可从文件重新扫描得到
- **静默写入是不允许的**：任何修改用户文件的操作都必须先预览影响面
- **音声元数据只存库内**：绝不写回音频文件

## 已知限制（V1.2.6）

| 限制 | 说明 |
| --- | --- |
| DLsite 索引不是全量 | 索引只含 DLsite「ボイス・ASMR」分类，且按**抓取时的地区**可见范围（换节点后会增减）。索引里声优只覆盖 72.7%（列表页只有主声优），社团覆盖 100%。查不到、或索引里那一条只有 RJ 没有数据（已下架作品）时，该专辑不补任何东西，等你手工填写 |
| 索引需要自己更新 | 索引由外部脚本每周增量抓取后整个文件替换；Luna 只读不写。替换 `data/Dlsite/rj_index.sqlite3` 后无需重启，下一次扫描就会用新数据 |
| 仅支持 ZIP | 7z / RAR / 分卷 / 加密包在 P4。**当前这些文件根本不被识别**：既不入库、也不计数、扫描报告里不会出现（静默跳过），只能自己解压成文件夹或转成 zip |
| 「从库中移除」只删索引 | 文件不动，所以它是"不再收录"而不是删除；恢复后需重新扫描才会回墙。库内记录（标签、收藏）随索引一起删除且不可恢复。音声发行按**发行根路径**记账，若之后重命名了那个文件夹，排除会失效（会被重新扫回），届时再移除一次即可 |
| 缓存只按容量回收 | LRU 不看时间维度；整张预读取为串行等待（大专辑会让进度浮层停留较久） |
| 图标源图仅 64×64 | 放大到 256 会偏软；16px 下花体字与波形不可辨 |
| 未实现 DSD / 整轨镜像的转码播放 | 此类文件可入库，但浏览器无法直接解码 |
| 视频版不参与音频队列 | 顺序播放时跳过视频 |
| 台本仅在无字幕时启用 | 同目录存在字幕文件时优先字幕，暂不能手动切换 |
| 100% 以上音量会削顶 | 软件放大只是把数字信号乘大：源文件本身已接近满刻度时，>100% 必然失真（已自动加软限幅压住爆音，代价是动态被轻微压缩）。要更响又不失真，优先调系统音量；按曲目响度归一（ReplayGain）尚未实现 |
