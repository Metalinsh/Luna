# Luna 测试流程

> 适用版本：V1.2.0
> 最后更新：2026-10-11

本文档定义 Luna 的**分级测试流程**。核心原则只有一条：

> **改哪里就测哪里；只有准备打包发布时，才跑完整流程。**

这样既保证质量，又不会因为每次改一行 CSS 就跑十分钟的全量测试而浪费资源。

---

## 1. 快速开始

```bash
pnpm test              # 局部：自动识别本次改动，只跑受影响的区域
pnpm test:unit         # 最快：只跑单元测试（约 1 秒，不启动软件）
pnpm test:full         # 完整：所有区域（发布前必跑）
pnpm test:list         # 列出所有区域及其覆盖范围

# 指定单个区域
node tools/check/run.mjs --area=lyrics
node tools/check/run.mjs --area=wall,detail

# 以某个提交为基准判断改动
node tools/check/run.mjs --changed --since=HEAD~1
```

运行器会在需要时**自动启动 Electron 开发实例**（检测到已有实例则直接复用），跑完再关掉，不需要手工开窗口。

---

## 2. 测试分层

| 层 | 位置 | 特点 | 何时跑 |
| --- | --- | --- | --- |
| 单元测试 | `test/*.test.mjs` | 纯 Node，临时目录建库，**不碰真实文件**，约 1 秒 | 每次改动 |
| 界面检查 | `tools/check/*.mjs` | 驱动真实 Electron 窗口，验证真实交互与 DOM | 相关区域改动后 |
| 手动工具 | `tools/dev/*.mjs` | 破坏性或探索性脚本，**不在自动流程内** | 需要时人工执行 |

单元测试与界面检查是互补的：单元测试保证逻辑正确，界面检查保证「真的点得动、看得见」。

---

## 3. 区域清单

每个区域对应一块功能，区域之间**断言不重复**——同一行为只在一个区域里验证。

| 区域 | 名称 | 覆盖内容 | 需要软件 |
| --- | --- | --- | --- |
| `unit` | 单元测试 | 路径解析、数据库与迁移、歌词格式、写入任务、维护逻辑 | 否 |
| `wall` | 专辑墙 | 卡片与角标、标签筛选、三个收藏入口、收藏视图不再空白 | 是 |
| `bulk` | 多选与批量填写 | 选择按钮样式、批量填艺术家/社团（仅 ASMR 生效） | 是 |
| `detail` | 专辑详情 | 曲目表布局、列宽拖动、双击名称播放、多艺术家显示 | 是 |
| `voice` | 音声专辑 | 版本与差分、特典、视频版、三层轨道模型、ASMR 自动打标 | 是 |
| `artist` | 艺术家与社团 | 以 artist 为准的识别、待确认提示、采用/保持现状、自动套用 | 是 |
| `lyrics` | 歌词与字幕 | LRC/VTT/SRT/ASS 识别解析、台本镜像目录、单曲详情布局、字号 A+/A− | 是 |
| `player` | 播放器 | 播放组件常驻、四种播放模式、单曲详情浮层与进度条 | 是 |
| `write` | 安全写回 | 副本校验、原文件入撤销区、撤销恢复 | 是 |
| `icon` | 图标资源 | ICO/PNG 生成与接入、侧栏品牌标、网页图标 | 是 |

### 3.1 改动 → 区域映射

映射规则写在 `tools/check/manifest.mjs` 的 `covers` 字段里。例如修改 `server/lyrics.mjs` 只会触发 `unit` 与 `lyrics`：

| 改动文件 | 触发区域 |
| --- | --- |
| `server/lyrics.mjs` | unit, lyrics |
| `server/asmr.mjs` | unit, voice, artist |
| `server/writers.mjs` | unit, write |
| `public/styles.css` | wall, detail, lyrics, player, icon |
| `public/index.html` | wall, bulk, player, lyrics, icon |
| `electron/main.cjs`、`build/`、`icon/` | icon |
| `docs/**`、`tools/dev/**` | 不触发任何区域 |

改动未命中任何规则时，运行器直接提示「无需运行测试」并成功退出。

## 4. 三种典型场景

### 4.1 日常开发：改完就跑局部

```bash
pnpm test
```

输出示例：

```
检测到 2 个改动文件
  · server/lyrics.mjs
  · public/app.js

运行模式：按改动自动选择
选中区域（4）：unit(单元测试)、wall(专辑墙)、detail(专辑详情)、lyrics(歌词与字幕)
...
总计：6 个检查项，失败 0 个
局部测试通过。发布前请再跑一次 --full 完整流程。
```

### 4.2 提交前：确认受影响区域全绿

```bash
pnpm test:unit                 # 逻辑层快速兜底
node tools/check/run.mjs --area=lyrics   # 针对性验证界面
```

### 4.3 发布前：完整流程

```bash
pnpm test:full
```

**只有 `--full` 全绿才允许打包。** 发布的第 2 步会自动再跑一次完整流程，测试不过直接中止打包（除非显式加 `--skip-tests`，仅限调试）。

## 5. 测试数据与清洁度

界面检查会读写开发库（`data/library.db`），必须遵守以下约定：

1. **每个套件开头重置自己关心的状态**，保证可重复运行，不依赖上一次的结果。
2. **测试写入的数据必须还原**。例如社团测试会先记下原值，结束时逐条写回；绝不使用「把所有社团清空」这类粗暴清理（历史上曾误删过真实数据）。
3. **单元测试绝不触碰 `E:\Music`**。所有文件操作都在 `os.tmpdir()` 下的临时目录里完成，结束即删。
4. `tools/dev/scan-check.mjs` 会删除真实索引记录，属于**破坏性手工工具**，不纳入自动流程。

## 6. 发布流程

```bash
pnpm release
```

`tools/release/build.mjs` 按顺序执行：

1. **前置检查** —— 版本号、`build/icon.ico`、Electron 运行时
2. **完整测试** —— 调 `run.mjs --full`，不过就中止
3. **清理旧产物** —— 删掉上一版的 exe 与 `win-unpacked`
4. **打包** —— electron-builder 生成免安装目录版 `Release/Luna_v1.2/Luna.exe`
5. **纯净数据** —— 在临时目录里新建一个空库，校验 `albums/tracks/tags/libraries` 全为 0 后，写入 `Release/data/`
6. **校验产物** —— 文件大小、重新打开库确认仍为空、`schema_version` 存在

### 6.1 为什么要「纯净数据」

开发期的库里会积累测试专辑、测试标签、收藏记录与封面缓存。直接打包会把这些东西带给用户，表现为主界面一打开就有一堆陌生专辑。

因此每次发布都会重新生成一个**只有表结构、没有任何记录**的 `library.db`，连同空的 `covers/`、`backup/`、`undo/` 一起放进 `Release/data/`。用户首次启动看到的就是干净的空库。

### 6.2 便携版的数据位置

主进程 `resolveDataDir()` 的决策顺序：

1. 环境变量 `LAM_DATA_DIR`
2. `<exe 同级>/data/` 下**存在 `library.db`** → 便携模式，数据跟着 exe 走
3. 否则退回 `%APPDATA%\Luna\data`

因为发布包里已经带了干净的 `library.db`，所以便携版开箱即用、数据不外溢。删掉 `Release/data/` 则会退回 APPDATA 模式。

## 7. 新增测试的约定

1. **先找区域再动手**。已有区域能覆盖就加在那里，不要新开一个「roundN-check」。
2. **不要重复已有断言**。如果某个行为已被别的区域验证，加一行注释指向它即可（现有代码里有这样的注释）。
3. 断言标签写清楚「**期望什么**」，并在括号里带上实测值，例如
   `ok('封面上方不与角标重叠', gap > 0, \`间隔 ${gap}px\`)`。
4. 新脚本放在 `tools/check/`，在 `manifest.mjs` 的对应区域里登记 `ui` 文件，并补充 `covers`。
5. 脚本结束必须 `process.exit(fail ? 1 : 0)`，运行器以退出码判定成败。
6. **结束时还原自己改过的数据**，参考 `check/bulk.mjs` 里的原值还原写法。

## 8. 命令速查

| 命令 | 说明 |
| --- | --- |
| `pnpm test` | 按改动自动选区域 |
| `pnpm test:unit` | 只跑单元测试 |
| `pnpm test:full` | 完整流程（发布前） |
| `pnpm test:list` | 列出区域 |
| `node tools/check/run.mjs --area=<id>` | 指定区域 |
| `node tools/check/run.mjs --full --no-app` | 复用已有实例，不自动启停 |
| `node tools/check/run.mjs --full --keep-app` | 跑完保留自己启动的实例 |
| `pnpm release` | 完整测试 + 打包 + 纯净数据 |
| `pnpm release -- --skip-tests` | 跳过测试打包（调试用） |
| `pnpm release -- --no-clean` | 不清理旧产物 |
