# 1. 产品概述

## 1.1 一句话定义

**把散落在硬盘里的本地音乐文件，整理成一面可浏览、可搜索、可播放的专辑墙，且绝不碰用户的音频文件本身。**

## 1.2 要解决的问题

| 用户痛点 | 现状 | 本产品的应对 |
| --- | --- | --- |
| 音乐散在多个盘符/多层目录，找一张专辑靠翻资源管理器 | 文件夹视图没有专辑概念 | 扫描后按专辑聚合成墙 |
| 播放器（Foobar/网易云）默认导入整库，夹杂无关内容 | 无法只管理"我的这批文件" | 用户显式指定音乐库目录，索引范围完全可控 |
| 音乐标签混乱，同一专辑的曲目聚不拢 | 播放器里出现"未知专辑"碎片 | 分组键 = 专辑艺术家 + 专辑名；缺失标签时按目录兜底归组 |
| 担心管理软件误删/改写文件 | 标签编辑类工具风险高 | **V1 全程只读**，任何操作都不写音频文件 |
| 想要好看的专辑墙但不想装重型软件 | 专用软件臃肿、要账号、要联网 | 零依赖前端，`node server/index.mjs` 即开即用 |

## 1.3 目标用户与场景

**画像 A｜收藏型听众（主要用户）**
本地有 500～20000 首精心整理的音乐，按"艺术家/专辑"分目录存放，标签基本规范。诉求：一眼看清自己有什么、快速定位、直接播放。关心封面墙的观感。

**画像 B｜古典/爵士爱好者（次要用户）**
专辑艺术家与曲目艺术家不同（如 `Karl Richter` vs 巴赫作品），依赖 `albumartist` 标签正确分组。对年份、格式、码率等信息敏感。

**画像 C｜临时整理者**
手头一批下载的音乐标签不全，只想先看看都是些什么、能不能听。对"未知专辑"的兜底归组有强需求。

**核心场景（按优先级）**

1. **看**：打开就是专辑墙，扫一眼知道库里有什么。
2. **找**：输入关键词（专辑/艺术家/曲目/流派/年份）立刻筛选。
3. **听**：点专辑播放整张，或点单曲播放，底栏常驻。
4. **盘**：统计页看总量、格式分布、年代分布。
5. **定位**：在软件里看到某首歌，一键在资源管理器里选中文件。

## 1.4 设计原则

| 原则 | 含义 | 在 V1 中的体现 |
| --- | --- | --- |
| **只读安全** | 任何功能都不得修改/移动/删除用户的音频文件 | 无任何写文件系统 API；"移除音乐库"仅删索引 |
| **零仪式启动** | 不装数据库、不配环境、不联网、不登录 | `node:sqlite` 内置 + 单条启动命令 |
| **索引即缓存** | 数据库随时可删可重建，音频文件是唯一事实来源 | 删除 `data/` 后重扫即恢复 |
| **渐进增强** | 标签缺失不导致功能不可用 | 四级兜底：标签 → 目录 → 文件名 → 占位图 |
| **本地优先** | 不发起任何外部网络请求 | 无遥测、无 CDN、无外部字体 |

## 1.5 非目标（V1 明确不做）

- ❌ 标签写回、批量重命名、文件移动/删除 —— **这是重要的安全承诺，不是能力缺失**
- ❌ 联网抓取封面/歌词/元数据（MusicBrainz、AcoustID 等）
- ❌ 多用户、账号、权限、云同步
- ❌ CD 抓轨、CUE 整轨分轨
- ❌ 移动端适配（窄屏布局未实现）
- ❌ 高解析音频的独占/直通输出（受浏览器 `<audio>` 能力限制）

# 3. 用户旅程与核心流程

## 3.1 首次使用（0 → 1）

```
打开页面 → 空状态引导（💿 还没有音乐）
   → 点「+」→ 弹窗粘贴路径 或「浏览…」调系统目录框
   → 点「添加并扫描」→ 后端登记音乐库并立即启动扫描
   → 左侧进度条：扫描文件 → 解析标签 → 清理失效条目 → 补充封面
   → 完成后自动刷新专辑墙 + Toast 汇总「新增 N，更新 M，清理 K，封面 C」
```

**设计要点**：扫描是"添加即触发"的，用户不需要理解"登记"和"扫描"是两个动作。失败路径全在弹窗内红字提示（目录不存在 / 不是目录 / 已在库中）。

## 3.2 日常使用

```
打开页面 → 专辑墙（默认按艺术家 A→Z）
   → 搜索框输入 → 实时筛专辑（260ms 防抖）
   → 点封面 ▶ → 整张入队并播放第 1 首
   → 点卡片 → 专辑详情 → 点某行 → 从该行起播
   → 底栏：进度拖拽（Range 请求）/ 音量 / 单曲循环 / 系统媒体键
```

## 3.3 文件增删后的重新扫描

```
新增/删除文件 → 点「扫描音乐库」
   → 新增文件被解析入库
   → 已存在且 size+mtime 未变的文件直接跳过（秒级完成）
   → 已删除的文件在「清理失效条目」阶段从索引移除
   → 变更文件的专辑若无封面，进入「补充封面」兜底
```

## 3.4 扫描状态机（后端 `scanState`）

```
idle → 准备中 → 扫描文件 → 解析标签 → 清理失效条目 → 补充封面 → 完成
                     ↑__________每个音乐库循环一次__________↓
任意阶段 → (用户取消) → 正在取消… → 已取消
```

| 字段 | 含义 |
| --- | --- |
| `phase` | 当前阶段文案（直接显示在侧栏） |
| `libraryIndex` / `libraryTotal` | 当前第几个音乐库 |
| `currentLibrary` | 当前音乐库路径 |
| `filesFound` / `processed` | 已发现音频文件数 / 已处理数（进度条分子分母） |
| `added` / `updated` / `skipped` / `removed` | 新增 / 更新 / 未变化 / 清理 |
| `coverExtracted` | 本次写入的封面数 |
| `failed` / `errors[]` | 失败计数 / 前 30 条错误详情 |

# 5. 功能规格（详细规则）

## 5.1 音乐库管理

| 规则 | 说明 |
| --- | --- |
| 路径归一 | `path.resolve()` 后存储；查重忽略大小写 |
| 校验 | 必须存在且为目录，否则 400 + 中文错误文案 |
| 添加后行为 | 默认立即触发该库的扫描（`scan: false` 可关闭） |
| 移除 | 删除该库全部 `tracks`，并清理因此变空的 `covers` 记录；**不动文件** |
| 重复添加 | 返回 200 且 `added: false`，但仍重新扫描 |

## 5.2 扫描引擎

**遍历规则**

| 规则 | 值 |
| --- | --- |
| 算法 | 显式栈迭代（非递归），避免深目录栈溢出 |
| 跳过目录 | `system volume information`、`$recycle.bin`、`node_modules`、`.git`、`.svn`、`__macosx`、`recycler`、`windows`、`$windows.~ws`、`$windows.~bt`，以及所有 `.` 开头的目录 |
| 跳过文件 | `.` 开头的隐藏文件 |
| 符号链接 | 一律跳过（防环） |
| 音频扩展名 | `.mp3 .flac .m4a .mp4 .m4b .aac .ogg .oga .opus .wav .aiff .aif .aifc .wma .ape .wv .dsf .dff .mpc .tak` |
| 并发 | 固定 4 个 worker 共享游标消费文件列表 |
| 取消 | `cancelRequested` 标志，worker 在每首歌边界检查；取消时**不做清理**（避免误删） |

**增量规则**

```
若 库中已存在该路径 且 size 相同 且 mtime(ms, 取整) 相同
   → 计入 skipped，完全不解析标签、不碰封面
否则 → 完整解析并 UPSERT（保留原 added_at）
```

**清理规则**

扫描某库成功后：`SELECT path FROM tracks WHERE library_id = ?` 中不在本次 `seen` 集合内的记录 → 删除（并清理变空的封面记录）。**取消扫描时跳过清理**。

**封面优先级**

1. 内嵌图片：优先 `type` 含 `front` 的，否则第 1 张；
2. 目录图片：按 `cover.jpg → folder.jpg → front.jpg → album.jpg → albumart.jpg → cover.jpeg → folder.jpeg → cover.png → folder.png → front.png → cover.webp → folder.webp` 顺序取第一个存在的；
3. 扫描末尾「补充封面」阶段：为所有**没有封面记录**的专辑再试一次目录图片（覆盖"封面后来才放进去"和"文件未变化被跳过"两种情况）。

封面以 **SHA-1 内容寻址**存为 `data/covers/<sha1>.<ext>`，DB 只记 `hash/file/mime/source`。内嵌封面优先级高于目录封面（同一专辑若已有目录封面、后来发现内嵌封面，会覆盖）。

**错误处理**

| 情况 | 行为 |
| --- | --- |
| 目录不可读 | 记录错误（含 `err.code`），继续下一个目录 |
| 音乐库路径消失 | 记录错误并跳过该库，**不执行清理**（防止整库索引被误删） |
| 单文件标签解析失败 | 仍入库，`parse_error` 记录错误摘要，标题回退为文件名，按目录归组 |
| 封面读取失败 | 记录错误，专辑无封面 |
| 错误累计 | `failed` 计数 + 前 30 条详情，界面 Toast 提示"详见服务端日志" |

## 5.3 专辑聚合规则

```
album_key =
  若 专辑名非空 → "alb\0" + (专辑艺术家 || 曲目艺术家).lower() + "\0" + 专辑名.lower()
  否则          → "dir\0" + 所在目录.lower()
```

- 展示名：专辑名空 → `(未知专辑)`；艺术家空 → `(未知艺术家)`（SQL 层 `COALESCE` 兜底）
- 曲目排序：`COALESCE(disc_no,1)` → `COALESCE(track_no,9999)` → 文件名（自然忽略大小写）
- `disc_count`：该专辑下 `DISTINCT disc_no` 的数量，>1 时卡片显示"N 碟"
- 专辑艺术家取该专辑内任意一条（实际数据中通常一致）

## 5.4 搜索与排序

**搜索**：单个关键词，`LIKE '%kw%' ESCAPE '\'`（转义 `\ % _`，避免用户输入 `%` 变成通配），作用字段：

`(未知专辑兜底后的专辑名)`、`(专辑艺术家兜底后)`、`曲目艺术家`、`曲目标题`、`流派`、`年份(转文本)`

**排序（8 种，`ORDER BY` 使用输出别名，规避裸列歧义）**

| 值 | 界面文案 | 排序规则 |
| --- | --- | --- |
| `artist-asc` | 艺术家 A→Z | 专辑艺术家 → 年份 → 专辑名 |
| `album-asc` | 专辑名 A→Z | 专辑名 → 专辑艺术家 |
| `album-desc` | 专辑名 Z→A | 专辑名倒序 |
| `year-desc` | 年份 新→旧 | 年份降序（NULL 最后）→ 专辑名 |
| `year-asc` | 年份 旧→新 | 年份升序（NULL 最后）→ 专辑名 |
| `added-desc` | 最近入库 | 该专辑内最大 `added_at` 降序 |
| `tracks-desc` | 曲目数 | 曲目数降序 → 专辑名 |
| `duration-desc` | 总时长 | 总时长降序 |

## 5.5 播放

| 规则 | 说明 |
| --- | --- |
| 传输 | HTTP，`Accept-Ranges: bytes` |
| 无 Range | `200` + `Content-Length` |
| 有 Range | `206` + `Content-Range: bytes s-e/total` + `Content-Length: e-s+1` |
| 后缀范围 | `bytes=-500` 解析为末尾 500 字节 |
| 越界/非法 | `416` + `Content-Range: bytes */total` |
| `HEAD` | 返回头部但不发送 body |
| 文件已消失 | `410 Gone`（前端提示文件被移动或删除） |
| 曲目不存在 | `404` |
| `?download=1` | 追加 `Content-Disposition: attachment`（RFC 5987 UTF-8 文件名） |
| MIME | 按扩展名映射；未知扩展名回落 `application/octet-stream` |
| 浏览器兼容 | 依赖浏览器解码能力：MP3/FLAC/M4A/AAC/OGG/Opus/WAV 主流可用；**APE/WavPack/DSD 通常无法播放**（可入库、可看、不可听） |

## 5.6 统计口径

| 指标 | 定义 |
| --- | --- |
| 专辑 | `COUNT(DISTINCT album_key)` |
| 曲目 | `COUNT(*)` |
| 艺术家 | `COUNT(DISTINCT COALESCE(NULLIF(album_artist,''), artist))`（**无名曲目不计数**） |
| 总时长 | `SUM(duration)`（**duration 为空的文件不计入**，实际会偏低） |
| 占用空间 | `SUM(size)` |
| 已获取封面的曲目 | `SUM(has_cover = 1)`（按专辑粒度标记，整张专辑共享） |
| 格式分布 | 按扩展名大写分组，计曲目数与总大小 |
| 年代分布 | `(year/10)*10`（整数除法），仅统计 `year > 1900`，计**专辑数** |
| 高产艺术家 | 同一艺术家归一规则，按专辑数降序取前 12 |

# 6. 数据模型

## 6.1 关系

```
libraries 1 ──── n tracks ──── 1 covers
   (id)         (library_id)     (album_key)
```

`covers` 以 `album_key` 为主键，与 `tracks` 的多条记录逻辑关联（非外键约束，靠应用层在删除时清理）。

## 6.2 表结构

**libraries**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | INTEGER PK | 自增 |
| `path` | TEXT UNIQUE | 归一后的绝对路径 |
| `added_at` | INTEGER | 登记时间戳（ms） |
| `last_scan_at` | INTEGER | 最近一次成功扫描时间 |
| `track_count` | INTEGER | 保留字段（列表查询实际用子查询实时统计） |

**tracks**

| 字段 | 类型 | 来源 |
| --- | --- | --- |
| `id` | INTEGER PK | 自增 |
| `path` | TEXT UNIQUE | 绝对路径 |
| `dir` | TEXT | 所在目录（分组兜底、封面回填用） |
| `library_id` | INTEGER | 所属音乐库 |
| `filename` / `ext` | TEXT | 文件名 / 小写扩展名（含点） |
| `size` / `mtime` | INTEGER | 增量判定依据（mtime 毫秒取整） |
| `title` | TEXT | `TIT2` → 文件名去扩展名 |
| `artist` | TEXT | `TPE1` / `artists[0]` |
| `album_artist` | TEXT | `TPE2` → 回落 artist |
| `album` | TEXT | `TALB` |
| `album_key` | TEXT | 分组键（见 5.3） |
| `track_no` / `disc_no` | INTEGER | `TRCK` / `TPOS` 的 `no` 部分 |
| `year` | INTEGER | `year` → 从 `date` 前 4 位解析 |
| `genre` / `composer` | TEXT | 数组取首个非空值 |
| `duration` | REAL | 秒（含小数） |
| `bitrate` | INTEGER | bps |
| `sample_rate` / `channels` | INTEGER | Hz / 声道数 |
| `codec` / `container` | TEXT | 如 `MPEG-4/AAC` / `mp42/isom` |
| `has_cover` | INTEGER | 该专辑是否有封面（插入时判定 + 回填时更新） |
| `parse_error` | TEXT | 解析失败摘要（`CODE: message`，截断 160 字符） |
| `added_at` / `updated_at` | INTEGER | 入库 / 更新（UPSERT 保留原 added_at） |

**索引**：`album_key`、`artist`、`album`、`library_id` 各一个。

**covers**

| 字段 | 说明 |
| --- | --- |
| `album_key` | PK |
| `hash` | 图片内容 SHA-1（也用作文件名） |
| `file` | `data/covers/` 下的文件名 |
| `mime` | `image/jpeg` 等 |
| `source` | `embedded` / `folder`（内嵌优先于目录） |
| `updated_at` | 写入时间 |

## 6.3 存储布局与重置

```
data/
├─ library.db         SQLite（WAL 模式，synchronous=NORMAL）
├─ library.db-wal/-shm
├─ covers/<sha1>.<ext>  内容寻址的封面缓存
└─ config.json       { port: 8787, host: "127.0.0.1" }
```

删除整个 `data/` 目录即完全重置，重新扫描可无损重建（**音频文件是唯一事实来源**）。端口也可用 `PORT` / `HOST` 环境变量覆盖。

# 7. API 契约

统一约定：JSON 请求/响应；错误返回 `{ error: "中文说明" }` + 恰当状态码。

| GET | `/api/stats` | — | `{ stats, libraries }` | 200 |
| GET | `/api/libraries` | — | `{ libraries[] }` | 200 |
| POST | `/api/libraries` | `{ path, scan? }` | `{ library, added }` | 201 新增 / 200 已存在 / 400 路径非法 |
| DELETE | `/api/libraries/:id` | — | `{ ok: true }` | 200 / 404 |
| POST | `/api/dialog/folder` | — | `{ ok, path }` 或 `{ ok:false, cancelled:true }` | 200 / 500 |
| POST | `/api/reveal` | `{ trackId? , path? }` | `{ ok: true }` | 200 / 400 / 404 |
| POST | `/api/scan` | `{ libraryIds? }` | `{ state }` | 202 / 409 已在扫描 |
| GET | `/api/scan/status` | — | `{ state, running }` | 200 |
| POST | `/api/scan/cancel` | — | `{ cancelled: boolean }` | 200 |
| GET | `/api/albums` | `q, sort, limit≤2000(默认300), offset` | `{ albums[], total, limit, offset }` | 200 |
| GET | `/api/albums/:key` | `:key` = base64url 专辑键 | `{ album, tracks[] }` | 200 / 400 / 404 |

| GET | `/api/stream/:id` | `Range` 头, `?download=1` | 音频流 | 200 / 206 / 404 / 410 / 416 |
| GET/POST | `/api/config` | `{ port?, host? }` | `{ config }` | 200 |
| GET | `/*`（非 `/api/`） | — | `index.html`（SPA 兜底） | 200 |

**专辑对象（列表）**

```json
{
  "key": "YWxiADAwMDA…",      // base64url 编码的专辑键（对外唯一标识）
  "album": "Bach: Toccata & Fugue",
  "album_artist": "Karl Richter",
  "artist": "Karl Richter",
  "year": 1970, "genre": "Classical",
  "track_count": 3, "duration_sum": 0,
  "has_cover": 0, "disc_count": 1,
  "cover_url": "/api/cover/<sha1>"   // 无封面为 null
}
```

> 内部 `album_key` 永不下发：列表与详情响应中该字段被显式置为 `undefined`，对外只暴露 base64url 的 `key`。

**安全设计**：内部 `album_key` 含 `\0`，对外一律以 base64url 暴露；`/api/albums/:key` 解码失败返回 400，不存在的专辑返回 404。

# 8. 非功能需求

| 维度 | 要求 | 当前达成情况 |
| --- | --- | --- |
| **性能-扫描** | 1 万首首次全扫可接受 | 并发 4 解析；二次扫描靠 `size+mtime` 跳过，接近磁盘遍历速度 |
| **性能-浏览** | 专辑墙滚动流畅 | ⚠️ 全量渲染 DOM，无虚拟滚动；600 张以内良好 |
| **性能-搜索** | 输入即响应 | ⚠️ `LIKE` 全表扫描 + 260ms 防抖；万首量级可用，十万首需 FTS |
| **性能-播放** | 拖动进度即时响应 | ✅ Range + 206，不重传整文件 |
| **可靠性** | 崩溃/重启不损坏数据 | ✅ SQLite WAL + `synchronous=NORMAL`；索引可重建 |
| **可靠性** | 扫描可取消、可重入 | ✅ 同一时刻仅一个扫描任务（409 拒绝并发） |
| **安全-数据** | 绝不修改音频文件 | ✅ 代码中无任何写音频路径 |
| **安全-网络** | 仅本机可访问 | ✅ 默认绑定 `127.0.0.1`；⚠️ 无鉴权，改 `HOST` 即暴露 |
| **安全-输入** | 防路径穿越 | ✅ 封面 hash 经 `path.basename()`；文件路径只从 DB 读取 |
| **兼容性** | Windows 10/11 + Node ≥ 22.5 | ✅ 实测 Node 24.21；⚠️ 目录框/定位依赖 Windows 组件 |
| **可维护性** | 无构建、无原生依赖 | ✅ 2 个纯 JS 依赖，`node server/index.mjs` 即运行 |
| **可测试性** | 可自动化验证 | ⚠️ 基线验证脚本未纳入仓库 |

# 9. 已知缺陷与技术债

> 编号供迭代时引用（如 "V1.1 修复 D2"）。

| 编号 | 等级 | 问题 | 影响 | 建议版本 |
| --- | --- | --- | --- | --- |
| **D1** | 中 | `pruneCoverIfOrphaned` 只删 `covers` 行，**不删 `data/covers/` 里的图片文件** | 反复换封面/移除音乐库后磁盘缓慢增长，无回收机制 | V1.1 |

| **D4** | 中 | 仓库内无自动化测试（基线验证为一次性脚本） | 迭代易引入回归（本次开发已实际出现 3 个 bug） | V1.1 |
| **D5** | 低 | 平台绑定：目录选择框依赖 `powershell.exe`、定位依赖 `explorer.exe` | 非 Windows 平台功能降级 | V2.0 |

| **D7** | 中 | "未知专辑"按**目录**归组；多碟专辑若分放 `CD1/CD2` 目录不会合并 | 同一专辑被拆成多张卡片 | V1.2 |
| **D8** | 中 | 无文件系统监听 | 新增音乐后必须手动扫描 | V2.0 |
| **D9** | 低 | 搜索为 `LIKE`，无 FTS、无拼音、无错字容错 | 大库搜索慢；中文拼音检索不可用 | V1.3 |
| **D10** | 低 | 无鉴权；`HOST=0.0.0.0` 时同网段可调用全部 API（含 `/api/reveal` 弹出资源管理器） | 误配置即暴露 | V1.1（文档警示）/ V2.0 |
| **D11** | 中 | 播放队列不可见、不可编辑（无队列面板），任何播放动作都会替换队列 | 无法"边听边加歌"，无法查看接下来播什么 | V1.3 |
| **D12** | 低 | 无歌词、无封面手动替换、无重复曲目检测 | 功能缺口 | V1.3 / V2.0 |
| **D13** | 低 | `scanState.lastError` 字段定义但从未赋值 | 死字段，易误用 | V1.1 |
| **D14** | 低 | 侧栏固定 260px，无窄屏/移动布局 | 小窗口下内容被挤压 | V2.0 |

# 10. 迭代路线图

## 10.1 优先级原则

1. **先可信，再能干**：数据正确性、大库完整性 > 新功能。
2. **写操作必须可撤销**：任何触碰文件的功能，都要有预览 + 备份 + 一键撤销。
3. **不破坏只读承诺**：读操作永远不写用户文件。
4. 每个版本必须交付**可验证的验收标准**，而不是"功能做完了"。

## 10.2 V1.1 —— 装得下大库、经得起长期运行（工程健壮性）

**目标**：把 V1 从"能用"推到"可信赖"，优先消灭 D2/D1/D4，为后续写操作打好安全底座。

| 项 | 范围 | 优先级 |
| --- | --- | --- |
| 专辑墙与曲目列表分页/无限滚动 | 滚动到底自动加载下一页（沿用现有 `offset`），顶栏显示"已显示 X / 共 Y" | **必须** |
| 封面文件回收 | 删除专辑/换封面时回收孤儿图片；启动时或手动触发一次 `gc` | **必须** |
| 自动化测试入仓 | `npm test`：API 契约断言 + 扫描器行为单测（用 fixtures 生成器）+ Range 边界 | **必须** |
| 扫描任务持久化 | 状态写入 DB，服务重启后可在界面看到"上次扫描：时间/结果" | **必须** |
| 扫描不阻塞浏览 | 解析与 DB 写入分批让出事件循环；扫描期间页面保持可交互 | 应该 |
| 错误可查看 | 前端可展开"扫描报告"面板，看 `errors[]` 全文而非只看计数 | 应该 |
| 时长缺失补救 | 二次估算或界面显示"—"而非误导性的 `0:00` | 应该 |
| 清理死字段 D13 | 移除或真正赋值 `lastError` | 可选 |

**验收标准**

- 库内 1200 张专辑时，界面可滚动查看全部，计数与 API `total` 一致；
- 执行"添加封面 → 删除音乐库 → 重新添加"，`data/covers/` 文件数不增长；
- `npm test` 全绿，且覆盖 Range 的 206/416/410 三类分支；
- 扫描期间拖动进度条播放、搜索、切换视图均无 >500ms 卡顿。

## 10.3 V1.2 —— 从"看"到"整理"（谨慎引入写操作）

**目标**：满足"标签乱、想修"的真实需求，同时用工程手段保证不可逆风险可控。

| 项 | 范围 | 优先级 |
| --- | --- | --- |
| 撤销基础设施 | 所有写操作前把原文件/原标签快照到 `data/undo/<batch>/`，提供"撤销上一批" | **必须** |
| 标签编辑 | 单曲与批量（专辑级）编辑：标题/艺术家/专辑艺术家/专辑/音轨/碟号/年份/流派 | **必须** |
| 批量重命名 | 模板（`%artist%/%year% - %album%/%track% - %title%`）+ 实时预览 + 冲突检测 | **必须** |
| 未知专辑归并 | 手动把多个目录的曲目合并到同一专辑（写入 `album_key` 覆盖） | 应该 |
| 多碟合并 | `CD1/CD2`、`Disc 1/2` 目录识别并合并为一张专辑 | 应该 |
| 封面手动替换 | 从本地选图或从同目录选图，支持"应用到整张专辑" | 应该 |
| 重复检测（保守版） | 时长 + 文件大小 + 标题归一化三重一致才提示，只提示不自动删 | 可选 |

**验收标准**

- 批量重命名 500 个文件后，可一键回到重命名前的路径与标签；
- 任何写操作中途失败（模拟磁盘错误）不留半个文件；
- 写操作前端全程二次确认 + 影响面清单（"将修改 N 个文件，涉及 M 张专辑"）。

# 12. 变更管理（如何基于本文档迭代）

每个迭代周期按以下流程推进，**文档始终是唯一基线**：

1. **需求条目化**：新需求写成"用户故事 + 验收标准"，并标注影响的功能规格章节号。
2. **影响面分析**：明确涉及的 API、数据表、视图与已知缺陷编号（如"顺手修复 D6"）。
3. **数据迁移评估**：任何表结构变更必须给出兼容旧 `library.db` 的迁移脚本（`data/` 是用户唯一不可重建资产之一 —— 索引可重建，但用户的音乐库配置不能丢）。
4. **实现与自测**：新增/修改的行为必须同步补充自动化测试（V1.1 之后为强制要求）。
5. **验收对照**：逐条勾选该版本的验收标准，未达标项必须记录原因。
6. **文档版本递增**：更新本文档顶部的版本号与「版本记录」表，并把已修复缺陷从第 9 章移除或标记 ✅。

**文档维护约定**

- 第 9 章（已知缺陷）只增不删，修复后加删除线并标注修复版本；
- 第 10 章路线图允许重排序，但目标表述不得悄悄放宽；
- 任何"V1 非目标"若要启动，必须先在本文档 1.5 节移除并给出安全设计。

# 附录 B｜术语表

| 术语 | 含义 |
| --- | --- |
| 音乐库（Library） | 用户显式登记的一个根目录，扫描范围的边界 |
| 专辑键（album_key） | 专辑聚合的内部标识，形如 `alb\0艺术家\0专辑名` 或 `dir\0目录` |
| 增量扫描 | 依据 `size + mtime` 跳过未变化文件，只解析新增/变更文件 |
| 回填（backfill） | 扫描末尾为无封面专辑重新查找目录封面图的阶段 |
| 内容寻址 | 以文件内容的 SHA-1 作为存储文件名，天然去重 |
| 隐式队列 | 播放列表由触发播放时的列表整体决定，无独立队列实体 |
