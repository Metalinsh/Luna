# 音声（ASMR）专辑管理设计

> 本文是 [`产品设计文档.md`](产品设计文档.md) 的**补充基线**，只描述音声类内容相对普通音乐专辑的差异与新增规则。
> 所有规则均以 `E:\Music` 下三张真实音声专辑为样本验证（RJ01113481 / RJ01128508 / RJ01182623）。

## 1. 为什么不能沿用普通专辑模型

| 维度 | 普通音乐专辑 | 音声专辑（实测） |
| --- | --- | --- |
| 组织单位 | 专辑（标签驱动） | **发行（RJ 号）** |
| 一个发行内 | 一张专辑 | **多个「版本」**（不同格式 / 不同差分 / 视频版） |
| 标签可用性 | 基本完整 | **大部分音频没有任何标签**（WAV 几乎全为空） |
| 专辑名来源 | `album` 标签 | **文件夹名**（标签里往往没有） |
| 艺术家 | 标签里有 | **通常没有**，由用户可选填写，**只存库不写回文件** |
| 封面 | 内嵌 | **基本没有内嵌**，靠专门的封面图文件夹 |
| 字幕 | 偶尔有 `.lrc` | 大量 `.vtt`（命名规则与 `.lrc` 不同） |
| 附属文件 | 少 | 台本/翻译/图片/PDF/视频，数量可达数百 |

**已有实证**：用现有模型扫描 RJ01113481 的结果是 **6 张叫「(未知专辑)」的卡片**（按目录归组），彼此看不出关系。必须改为三层模型。

## 2. 三层模型

```
发行 Release        ← 一个 RJ 号 = 专辑墙上一张卡
 ├─ 版本 Version    ← 可播放/可切换的完整一套轨道（如 本篇wav / 无音效wav / 视频版）
 │   └─ 轨道 Track  ← 按轨号对齐，跨版本合并显示
 └─ 特典分组 Bonus   ← 不属于主轨道的附加轨道（收起显示）
```

- **版本**是"同一批轨道的不同呈现"：格式差异（mp3/wav）、内容差分（无音效/无饮尿/SEcut/nonSE/Voice）、视频版。
- **特典**是"额外的轨道"，与版本正交：它有自己的轨道集（可能只有 1 条）。
- **视频不是独立轨道**，而是某条轨道的**一个版本**，在轨道行上以「视频版」tag 呈现。

## 3. 路径解析规则（R1–R15）

### R1 发行根识别
- RJ 号形如 `[RJ01182623]…` 或 `…[RJ01187370]…`，正则 `RJ\d{6,8}`。
- 路径中**最靠外**的 RJ 目录 = **发行根**。
- 发行根内层若再出现 RJ 目录 → 该目录是**特典子发行**，**并入本体**（卡片上标注「含特典版本」），不单独成卡。

实测：`[RJ01182623]…/05：特典/…/[RJ01187370]…特典/trackEX_…` → 归属 RJ01182623，标记含特典。

### R2 版本目录提取
- 从文件所在目录**向上直到发行根**，收集目录链。
- 剔除**格式包装目录**：名称归一化后仅由「格式词 + 可选的序号/括号说明」构成，格式词 ∈ {`mp3`,`wav`,`flac`,`aiff`,`m4a`,`视频`,`video`,`形式`}，可带 `（…）` 说明与 `320kbps/48KHz` 之类的参数。
  例：`（mp3）`、`01：mp3`、`02_wav`、`05_mp3形式（320kbps_48KHz）`、`04_带字幕的音频视频`
- 剔除与发行同名/近同名的**专辑包装目录**（如 RJ01113481 里那层重复的专辑名目录）。
- 剩余链的**最后一段** = **版本名**；链为空 → 版本名取「本篇」。

实测：
| 文件路径（相对发行根） | 版本名 |
| --- | --- |
| `本篇（mp3）/01…mp3` | 本篇 |
| `本篇（wav）/无音效（wav）/01…wav` | 无音效 |
| `本篇（wav）/无饮尿（wav）/06…wav` | 无饮尿 |
| `01_通常ver/01…wav` | 01_通常ver |
| `05_mp3形式（320kbps_48KHz）/01_通常ver/01…mp3` | 01_通常ver |
| `05_mp3形式（…）/04_Voice（声のみ_mp3）/01…mp3` | 04_Voice（声のみ） |
| `01：mp3/track00…mp3` | 本篇（链被清空） |
| `03：SEcut（效果音剪辑版）/01：mp3/track01…mp3` | 03：SEcut（效果音剪辑版） |

### R3 版本名归一化（用于跨格式对齐）
依次处理：全角转半角 → 去除格式标记（`_mp3`/`_wav`/`（mp3）`/`（wav）`/`320kbps`/`48KHz` 等）→ 去除首尾空白与多余空格 → 转小写。
**保留序号前缀**（`01_` 与 `02_` 不会被判为同一版本）。

### R4 格式判定
**以文件扩展名为准**，不依赖目录名（实测目录命名极不统一）。
- 音频：`.mp3 .wav .flac .m4a .aac .ogg .opus .wma`
- 视频：`.mp4 .mkv .webm .m4v .mov`

### R5 wav 优先（**按版本**，非按整张专辑）
同一发行内，**同一个版本**若同时存在 wav 与 mp3 版本 → 只收录 wav；**仅 mp3 存在的版本照常收录**。

> ⚠️ 这是必须按版本判断的原因：RJ01128508 的 wav 侧有 3 版（通常/nonSE/Voice+SNAP），mp3 侧有 4 版（多一个 `04_Voice`），
> 若按"整张有 wav 就丢 mp3"，`04_Voice` 的 14 个文件会彻底消失。

实测版本数：RJ01113481 → **3 版**；RJ01128508 → **4 版**（3 wav + 1 mp3）。

### R6 视频版本
- 仅当视频文件与某个音轨**同主名**（去掉扩展名后相等）时，才视为该轨道的**视频版**。
- 视频目录下的子目录（如 `有日文字幕/`）视为视频版的**子变体**，不额外增加版本数。
- 与任何音轨都不同主名的视频（动态壁纸 / 促销视频 / 闹钟视频）→ 按 R7 处理。

实测：`04：带字幕的音频视频/track00_读标题.mp4` ↔ `01：mp3/track00_读标题.mp3` 同主名 ✓

### R7 忽略规则（不收录）
路径任一段匹配以下关键词 → 整棵子树忽略：
`闹钟` `目覚まし` `alarm` `动态壁纸` `Live Photos` `livephoto` `促销` `宣传` `promo` `试听` `サンプル`
非音频/非视频的附属文件（`.txt .pdf .jpg .png .vtt .lrc`）不参与轨道，交给 R13/R16 处理。

### R8 特典分组
路径任一段匹配 `特典` `おまけ` `おまけ` `bonus` `extra` `EX`（大小写不敏感）→ 该轨道归入**特典子分组**，不参与主轨道列表，界面收起显示。

### R9 轨道序号提取
按优先级从文件名取序号：`^\d{1,3}[._\-\s]`（`01_` / `01.` / `01 `）、`^track(\d{1,3})[._\-\s]`、`^EP[._\-\s]`（EP 排最后）。
无序号 → 序号 = ∞，按文件名排序。

### R10 跨版本轨道对齐
轨道键 = 归一化后的「序号 + 主标题」（主标题取文件名去掉序号前缀的部分，去扩展名，去差分后缀如 `(SECut)`、`（无音效）`、`_nonSE`、`_Voice`）。
同一键在多个版本中出现 → 合并为**一行**，行内提供版本切换。
**不使用内嵌标签的 track 号**：实测 RJ01128508 的 mp3 标签 track 是 1–15/16–29/30–43/44–57 的**全局流水号**，与版本内轨号不对应。

### R10+ 相似度合并（自动合并 + 待确认）
发布者的文件名常有笔误，导致同一条轨道被拆成两行。策略是「能自动合并的自动合并，把握不足的交给人工」：

| 判定 | 处理 |
| --- | --- |
| 数字签名不同（如 `DAY01_01` vs `DAY01_02`） | **绝不合并** |
| 一侧有「前篇」另一侧有「后篇」等篇章标记 | **本就是不同轨道**，不合并也不提示 |
| 两键有包含关系 且 短键占比 ≥ 0.6 且（来自不同版本 或 多出的部分是已知差分标记） | **自动合并** |
| 编辑距离相似度 ≥ 0.9 且来自不同版本 | **自动合并** |
| 其余相似（包含关系 或 相似度 ≥ 0.82） | 记入 **mergeCandidates**，界面提示人工确认，暂不合并 |
| 键长度 < 3 | 不参与合并（避免单字误合） |

实测命中：`…DAY05_通話` 与 `…DAY05_通話_通話` 自动合并；`…初次不孕神疗（前篇）` 与 `（后篇）` 被正确判定为不同轨道（不产生噪音）。

### R11 发行标题
优先用内嵌标签的 `album`（最完整，含日文原名）；无标签（WAV 常态）→ 取**文件夹名**，去掉 `[RJxxxxxxxx]` 前缀与方括号。
实测：目录 `即おち!～_city girls_～…`（`"` 被文件系统替换为 `_`），而标签里是 `即おち!〜"city girls"〜…` → **标签更准确**。

### R12 艺术家
- 可从内嵌标签读取（若存在）；
- **主要由用户手工填写，仅存库，绝不写回音频文件**。
- 音声专辑默认**不参与写回流程**（见第 6 节）。

### R13 封面
按优先级在发行根内查找：
1. 目录名含 `高画质封面图` / `封面` / `cover` / `package` 的目录内的图片；
2. 文件名含 `package` / `artwork` / `cover` / `封面` / `jacket` 的图片；
3. 发行根或专辑目录内的其他图片（取尺寸最大的一张）。
选中项写入 `albums.cover_*`（`source='manual'`），**不写回任何文件**。

实测：RJ01182623 → `05：特典\01：高画质封面图\st_a01.jpg`；RJ01128508 → `イラスト\SOKUOCHI_008_package_2560.png`。

### R14 冲突检测（人工确认）
比对三个来源：**文件夹名（权威）** / **文件名** / **内嵌标签**。
- 版本标识冲突（如文件夹说「无饮尿」、文件名说「饮尿」、标签说「飲尿なし」）→ 生成冲突记录，标红提示，用户确认后记住结论。
- 标题冲突（R11 的标签 vs 文件夹）→ 默认采用标签，不提示（这属于正常差异）。
- **产品不自动重命名文件**（重命名是写操作，需用户手动执行）。

实测冲突样本：`RJ01113481\…\无饮尿（mp3）\06.…（无音效、饮尿）.mp3` —— 文件夹名/文件名/标签三方不一致。

### R15 跨专辑同作品
若两个不同发行根下存在**同名同长度**的轨道 → **不自动合并**，在界面上提醒用户"疑似同一作品在多处出现，请选择收录哪一个"。

## 4. 数据模型（实现说明）

实际实现为「复用 `albums` 作为卡片 + 新增版本表」，而不是另建 `releases` 表——这样标签、封面、完整性检测、专辑墙等既有能力对音声发行**直接生效**：

```
albums                    音声发行的「卡片」
  kind = 'voice'          ← 与普通音乐专辑区分（普通为 'music'）
  rj_code, release_root   发行根与 RJ 号
  has_bonus, has_video    角标依据
  title / album_artist    标题取自文件夹或标签；艺术家仅库内记录（R12）

album_versions            版本
  album_id, name, name_key, group_kind('main'|'bonus'),
  preferred_format, file_count, total_bytes

tracks（已有表，新增列）
  version_id              所属版本
  track_key               跨版本对齐用的轨道键（界面按它合并成一行）
  file_kind               'audio' | 'video'
  variant_label           视频子变体标签（如「有日字幕」）
  is_bonus                特典轨道

track_merge_decisions     人工对「相似轨道是否合一」的确认结论
  album_id, key_a, key_b, decision('merge'|'separate')
```

收录范围遵循 R5「仅使用优先版本」：同一版本内只把优先格式（wav 优先）的文件写入 `tracks`，
未经采用的重格式文件**不入索引**（扫描收尾时会清掉历史遗留），避免界面上出现重复条目。
视频文件作为所属轨道的「视频版」单独收录，以便一键播放。

### 4.1 单发行重扫

`scanner.rescanReleaseRoot({ releaseRoot, libraryId })` 只重解析一个发行，
用于「人工合并结论」立即生效，以及单张刷新，不影响其它专辑。

## 5. 界面（已实现）

| 位置 | 表现 |
| --- | --- |
| 专辑墙卡片 | 角标：`N 个版本`；含特典时额外标 `含特典`；有视频版轨道时标 `含视频版`；RJ 号可见可搜 |
| 轨道列表 | **按轨号合并成一行**（如 12 行）；每行右侧是版本切换 chips（`本篇` / `无音效` / `无饮尿` / `视频版`）；点 chip 即切换播放源 |
| 视频版 | 该轨有视频时，版本 chips 里出现 `视频版`（带 ▶ 图标），点击一键播放；**没有视频版的轨道不显示该 chip** |
| 特典分组 | 轨道列表下方独立小节「特典（N 条）」，默认收起 |
| 冲突提示 | 卡片与轨道行上标 ⚠，点击进入冲突确认 |
| 详情页 | 显示 RJ 号、版本清单（含未入选的版本及原因）、文件总大小 |

## 6. 写回策略（音声专属）

音声专辑**默认不参与写回**：
- 专辑名取自文件夹名（R11），不是文件里的标签；
- 艺术家仅存库（R12）；
- 因此"编辑信息"对音声专辑只改数据库，**不产生任何写任务**，界面明确标注「仅记录在软件内」。

若将来需要写回（例如给 mp3 补标签），必须单独开启并按 V2.2 的八步流程执行。

| 现象 | 样本 | 处理 |
| --- | --- | --- |
| 基名尾部重复格式词 | `…彗の乳首責めwav.wav`（5 个） | 归一化（扩展名才是格式权威） |

| 版本内多文件 | 同一轨有 mp3+wav+视频 三个文件 | 版本内按轨道键保留**全部**文件 |

## 8. 尚未确认的边界

| # | 问题 |
| --- | --- |
| Q1 | 同一发行内不同版本若轨道**数量不同**（如 RJ01128508 的 15/14/14/14），合并后的行数取哪个版本的轨道集？（当前设计：取轨道数最多的版本为主集合，其余版本缺失的行显示为空） |
| Q2 | 视频版有子变体（中文字幕 / 日文字幕）时，是显示成一个 `视频版` chip 再二级选择，还是两个 chip？ |
| Q3 | 「特典」里如果也存在多版本（如 trackEX 有 mp3/wav/SEcut 三份），是否同样按 R5 只留 wav？ |
| Q4 | 发行根下与音轨无关的视频（促销视频等）是否需要在界面上列出（作为"其他资源"），还是完全隐藏？ |
