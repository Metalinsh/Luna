### v1.2.9（2026-11-16）
- **播放器键盘快捷键**（音频 / 视频同一套）：`空格` 播放暂停、`→` / `←` 快进快退 5 秒、`↑` / `↓` 音量 ±5%（复用 `applyVolume`，含 0–200% 软件放大）、`Ctrl+Alt+→` / `Ctrl+Alt+←` 下/上一首；`Shift+→` / `Shift+←` 也仍是上/下一首；输入框内不抢键。
- **单曲详情页后退**：`Alt+←` 与**鼠标侧键（X1）**关闭 `#nowPlaying` 浮层，等价于左上角返回（回到进入前的页面，不改 URL、不退浏览历史）；浮层没开时才真正 `history.back()`。系统级后退在 `electron/main.cjs` 拦（`app-command: browser-backward` + `before-input-event`），再经 `executeJavaScript('window.lunaBack?.()')` 转给页面，渲染进程另有同名监听与 250ms 去重（浏览器模式用）。**键位判断顺序**：先判 `Ctrl+Alt+←/→`（切曲），再判 `Alt+←`（后退），否则切曲会被后退吃掉。
- **专辑墙排序**：新增 `最近更新`（`albums.updated_at`，**打标签也算一次更新**，见 `applyAlbumTags`）、`收藏时间`（`favorite_at`，未收藏排最后）、`RJ号 小→大 / 大→小`（无 RJ 都排最后）四个排序键，共 13 项；排序仍是服务端 `ORDER BY`（`server/db.mjs` 的 `SORT_OPTIONS`），下拉在顶栏、选择存 `localStorage`。顺带修掉「收藏视图里换排序不生效」——原先只在 `view==='albums'` 时重载，现在 `ALBUM_WALL_VIEWS` 三个视图都会立即重载。
- **快捷键可配置（设置 → 快捷键）**：8 个动作（播放暂停 / 快退 / 快进 / 音量± / 上下一首 / 返回）全部可在设置面板里重新绑定。键位字符串存 `config.json` 的 `shortcuts` 段，格式是 `Ctrl+Alt+<KeyboardEvent.code>`（与键盘布局无关）；点键位按钮后直接按键即录制，ESC 取消，撞到保留键（L / E / 1-3 / `Ctrl+Alt+L` / `Ctrl+Alt+R` 等）或其它动作会被拒绝；支持逐项恢复默认，面板底部「恢复默认」也会一并重置。服务端 `server/config.mjs` 的 `normalizeShortcut()` 做格式校验与重复回退，前端 `SHORTCUT_ACTIONS` 只保留展示与默认值。**鼠标侧键后退固定，不进设置**。
- **专辑详情拖动排序（v13）**：曲目行行首加 `⠿` 拖动柄（Pointer Events，桌面/触屏/CDP 同一套），拖动后**立即改 DOM 与本地数组**再异步 `POST /api/albums/:id/track-order`，失败会重新拉详情回滚。「播放专辑 / 播放本版本」直接吃新数组，所以播放顺序立即生效。顺序存 `albums.track_order`（JSON 行键数组：普通专辑 `tracks.id`、音声 `row.key`，特典带 `bonus:`），扫描后仍有效、新曲目排在已有序行之后；有自定义顺序时行号显示播放位次，表格上方出现「已自定义播放顺序 · 恢复默认顺序」。服务端只接受属于该专辑的行键，未知键丢弃并回报数量。
- **测试**：`player` 新增「需求5–7」13 条断言（含视频版与 Ctrl+Alt 切曲），实测 39/0；`wall` 新增 4 条排序断言，实测 32/0；`settings` 新增快捷键自定义 9 条断言，实测 60/0；`detail` 新增拖动排序 11 条断言，实测 24/0；`desktop-lyrics` 33/0；单测 250/0（含 `test/sort.test.mjs`、`test/shortcuts.test.mjs`、`test/track-order.test.mjs`）。主进程拦截链路另做过一次临时 `sendInputEvent` 端到端验证，自定义键位（P 播放暂停）也做过运行时冒烟（验证后均已清理）。

## 4. 桌面歌词的关键实现（改之前先看）

- 窗口由 `server/desktop-lyrics.mjs` 在 **Electron 主进程里直接创建**（服务端就跑在主进程），不需要 preload / IPC。
- 播放状态：主窗口 `public/app.js` 通过 `BroadcastChannel('luna-playback')` 广播 `track / lyrics / time`；歌词页 `public/desktop-lyrics.js` 只渲染。
- 歌词窗 `focusable: false`，避免 Windows 透明窗失焦后冒出系统标题栏（Electron #46882 / #47440）。
- 单行适配逻辑在 `fitCurrent()`：先换行，再按可用宽高逐级缩字号。
- 工具条命令：歌词页发 `{type:'cmd', action}`，主窗口 `runLyricCommand()` 执行（音频元素只在主窗口）。
- 右键菜单是独立小窗 `public/desktop-lyrics-menu.html/js`，由主进程 `openMenu()` 创建，失焦自动关。
- 白条兜底：`scheduleCaptionFix()` 在主窗口 blur 后重建歌词窗；手动入口 `Ctrl+Alt+R` 与右键菜单「刷新歌词窗口」。

## 5. 已知限制 / 待办（新对话可直接从这里挑）

1. **白条是否彻底解决未确认**：v1.2.8 用「失焦重建」换掉标题栏，切换窗口时可能看到**一次很短的闪烁**；若用户仍遇到，考虑升级 Electron 37.x 或换窗口类方案。
2. **横向滚动被替换**：单行模式现在是换行+缩字号，和 v1.2.7 的横向匀速滚动是两种取舍。用户若要回滚动，可加配置开关，而不是二选一。
3. **右键菜单 / 托盘 / 全局快捷键**：目前只有接口层测试，菜单 UI、托盘菜单、快捷键冲突都靠人工；PR 新增代码尚未逐行 review。
4. **桌面歌词不随启动自动打开**：有意为之（避免一开软件弹窗、也避免干扰自动化检查）；位置/字号/颜色/描边/透明度仍记忆。
5. **Android 移植**：只做过工作量评估（PWA 1–3 周；原生 MVP 6–10 周；功能对齐 3–5 个月），**未开工**，用户已搁置。
6. **自定义播放顺序绑定行键**：普通专辑用 `tracks.id`、音声用 `track_key`；改标题/轨号后该行会回到自然顺序，重新入库（专辑 id 变化）不保留顺序 —— 都属于可接受边界，界面有「恢复默认顺序」。
7. **拖动排序不影响正在播放的队列**：改完从下一次播放/切曲起生效（当前队列不重排）。
8. **PR 分支**：`yarimuz/feat/desktop-lyrics-enhance` 已合并；本地保留 merge commit `a07c48a`。
