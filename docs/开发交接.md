## 4. 桌面歌词的关键实现（改之前先看）

- 窗口由 `server/desktop-lyrics.mjs` 在 **Electron 主进程里直接创建**（服务端就跑在主进程），不需要 preload / IPC。
- 播放状态：主窗口 `public/app.js` 通过 `BroadcastChannel('luna-playback')` 广播 `track / lyrics / time`；歌词页 `public/desktop-lyrics.js` 只渲染。
- 歌词窗 `focusable: false`，避免 Windows 透明窗失焦后冒出系统标题栏（Electron #46882 / #47440）。
- 单行适配逻辑在 `fitCurrent()`：先换行，再按可用宽高逐级缩字号。
- 工具条命令：歌词页发 `{type:'cmd', action}`，主窗口 `runLyricCommand()` 执行（音频元素只在主窗口）。
- 右键菜单是独立小窗 `public/desktop-lyrics-menu.html/js`，由主进程 `openMenu()` 创建，失焦自动关。
- 白条兜底：`scheduleCaptionFix()` 在主窗口 blur 后重建歌词窗；手动入口 `Ctrl+Alt+R` 与右键菜单「刷新歌词窗口」。

## 5. 已知限制 / 待办（新对话可直接从这里挑）

1. **白条是否彻底解决未确认**：v1.2.8 用「失焦重建」换掉标题栏，切换窗口时可能看到**一次很短的闪烁**；若用户仍遇到，考虑升级 Electron 37.x 或换窗口类方案。
2. **横向滚动被替换**：单行模式现在是换行+缩字号，和 v1.2.7 的横向匀速滚动是两种取舍。用户若要回滚动，可加配置开关，而不是二选一。
3. **右键菜单 / 托盘 / 全局快捷键**：目前只有接口层测试，菜单 UI、托盘菜单、快捷键冲突都靠人工；PR 新增代码尚未逐行 review。
4. **桌面歌词不随启动自动打开**：有意为之（避免一开软件弹窗、也避免干扰自动化检查）；位置/字号/颜色/描边/透明度仍记忆。
5. **Android 移植**：只做过工作量评估（PWA 1–3 周；原生 MVP 6–10 周；功能对齐 3–5 个月），**未开工**，用户已搁置。
6. **开发库 config 可能残留测试值**：`data/config.json` 的 `desktopLyrics` 可能在试用/测试后留下 `opacity: 0`、`fontScale ≈ 1.7` 等；交付前可手动恢复或忽略（只影响开发库）。
7. **PR 分支**：`yarimuz/feat/desktop-lyrics-enhance` 已合并；本地保留 merge commit `a07c48a`。
